## Session: sign-up readiness keeps polling past 45s (2026-11-09)
- New `assistant/src/web/app/readiness-poll.ts`: `readinessPollDelays()` returns a fresh copy of `[5000, 10000, 15000, 20000, 30000 ×8]` (12 gaps, 290000ms total, ~4m50s) and `READINESS_POLL_CAP_MS` is that sum, computed by `reduce` so the constant can never drift from the schedule. These are gaps between probes, not absolute offsets.
- `ConsumerApp.tsx` readiness effect only: the three one-shot timers at 5s/20s/45s are replaced by a sequential poll. Each gap is armed with `setTimeout` only after the previous `api.bootstrap()` settled, so there is never more than one request in flight. It stops when `next.identity?.signupAvailable` is true, when the schedule runs out, or on unmount; `bootstrap()` rejections are swallowed and the next gap still runs. `document.visibilityState === 'hidden'` re-arms the same gap instead of probing, so a background tab waits rather than hammering the API.

A production deployment without persistent identity can never open sign-up, so polling it for five minutes was pure waste. Effect deps are `boot?.identity?.persistent` and `boot?.identity?.signupAvailable`; a probe that sets `boot` without flipping either flag does not restart the chain.
